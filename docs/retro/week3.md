# 3주차 팀 회고 (KPT)

## 1. 회고 개요

- **팀명:** 취업할거조
- **참여자:** 최진영, 강민하, 조성식, 황상경, 권우리
- **목적:** 3주차 프로젝트 마무리 및 최종 발표 준비 과정에서 좋았던 점과 개선할 점을 공유하고, 향후 프로젝트에 적용할 협업 규칙을 정한다.

---

## 2. 팀원별 KPT

### 최진영

**Keep (계속할 점)**

- 팀원들의 피드백을 적극적으로 수용하고 작업에 반영함.

**Problem (개선할 점)**

- 팀원 간 작업 진행 상황이 원활하게 공유되지 않아 업무 분담 및 일정 조율에 어려움이 있었음.
- 일부 팀원에게 업무가 집중되면서 작업 부담이 불균형하게 발생함.

**Try (시도할 점)**

- 담당 업무의 진행 상황과 완료 여부를 기록하여 팀원들과 공유하기.
- 각자 맡은 업무에 책임감을 가지고 참여하며, 작업 진행 상황을 주기적으로 확인하기.

### 강민하

**Keep (계속할 점)**

- 프로젝트 진행 과정에서 자신의 의견을 적극적으로 제시함.

**Problem (개선할 점)**

- 최종 발표 자료 및 프로젝트 문서 작성이 계획대로 원활하게 진행되지 못함.

**Try (시도할 점)**

- 역할 분담 이후 각자 담당한 작업을 책임감 있게 완료하기.
- 작업 일정과 진행 상황을 확인하여 발표 자료 및 문서 작성이 지연되지 않도록 관리하기.

### 조성식

**Keep (계속할 점)**

- 담당한 작업에 책임감을 가지고 지속적으로 확인하며 진행함.

**Problem (개선할 점)**

- ERD 작성 시 1:N 관계를 중심으로 설계하여 연관 데이터가 존재하지 않는 0건의 상황을 충분히 고려하지 못함.

**Try (시도할 점)**

- 데이터 관계 설계 시 1:N 관계뿐 아니라 연관 데이터가 0건인 상황도 함께 고려하기.
- ERD 작성 후 다양한 데이터 생성 및 조회 상황을 검토하여 설계의 완성도 높이기.

### 황상경

**Keep (계속할 점)**

- 코드 및 문제 상황에 대한 피드백을 적극적으로 수용하고 개선 사항을 반영함.

**Problem (개선할 점)**

- Git 저장소를 최신화하지 않은 상태에서 작업을 시작하는 경우가 발생함.

**Try (시도할 점)**

- 작업 시작 전 원격 저장소의 최신 변경 사항을 확인하고 반영하는 습관 기르기.
- Git 최신화 절차를 작업 시작 전 필수 점검 사항으로 인식하기.

### 권우리

**Keep (계속할 점)**

- 코드 작성 중간에 기능 테스트를 진행하여 오류를 조기에 발견하고 수정 시간을 단축함.

**Problem (개선할 점)**

- 다른 팀원이 GitHub에 반영한 변경 사항을 충분히 확인하지 않아 테스트 과정에서 어려움이 발생함.

**Try (시도할 점)**

- PR 및 병합 과정에서 변경되거나 추가된 코드를 확인하는 습관 기르기.
- 다른 팀원의 변경 사항을 파악한 후 테스트를 진행하여 기능 간 연동 문제를 예방하기.

## 3. 공통 회고

### Keep

- 팀원들이 피드백을 수용하고 개선 사항을 작업에 반영함.
- 각자 담당한 기능과 작업을 지속적으로 확인하며 프로젝트를 진행함.
- 개발 과정에서 중간 테스트를 진행하여 오류를 조기에 발견하고 수정함.
- 프로젝트 진행 과정에서 자신의 의견을 제시하며 개선 방향을 논의함.

### Problem

- 작업 진행 상황 및 완료 여부가 충분히 공유되지 않아 업무 분담과 일정 조율에 어려움이 발생함.
- 일부 팀원에게 작업이 집중되면서 업무 부담이 불균형하게 발생함.
- 최종 발표 자료 및 문서 작성이 계획대로 진행되지 못함.
- Git 최신화 및 변경 사항 확인이 미흡하여 협업과 테스트 과정에서 문제가 발생함.
- 데이터 설계 시 다양한 예외 상황과 데이터 관계를 충분히 고려하지 못함.

### Try

- 담당 업무의 진행 상황과 완료 여부를 문서로 기록하여 팀원들과 공유하기.
- 역할 분담 시 담당자와 완료 일정을 명확하게 정하고 각자 맡은 작업을 책임감 있게 수행하기.
- 작업 시작 전 Git 최신화 여부를 확인하고 PR 및 병합된 변경 사항을 검토하기.
- 기능 구현 과정에서 중간 테스트를 진행하고 다른 기능과의 연동 여부를 확인하기.
- 데이터 설계 및 기능 구현 시 일반적인 상황뿐 아니라 예외 상황도 함께 검토하기.

## 4. 향후 프로젝트 팀 규칙

**선정 규칙: 작업 진행 상황 공유 및 담당 업무에 대한 책임 강화하기**

### 실천 방법

1. 업무 분담 시 담당자, 작업 내용 및 완료 일정을 명확하게 정한다.
2. 각 팀원은 담당 업무의 진행 상황과 완료 여부를 공유 문서에 기록한다.
3. 작업이 지연되거나 문제가 발생한 경우 즉시 공유하여 업무 분담과 일정을 조정한다.
4. 작업 시작 전 Git 저장소를 최신화하고, PR 및 병합된 주요 변경 사항을 확인한다.
5. 담당 기능은 구현 후 테스트까지 진행하며, 발견한 문제와 수정 내용을 공유한다.
6. 발표 자료 및 프로젝트 문서는 담당 파트를 기한 내 완료하고, 최종 검토 시간을 확보한다.

### 기대 효과

- 작업 진행 상황의 가시성 확보 및 원활한 일정 관리
- 특정 팀원에게 집중되는 업무 부담 완화
- 담당 업무에 대한 책임감 및 협업 효율 향상
- Git 충돌과 기능 간 연동 오류 예방
- 발표 자료 및 프로젝트 문서의 완성도 향상

- [ ] 담당 업무의 진행 상황과 완료 여부를 주기적으로 공유하였는가?
- [ ] 작업 지연이나 문제 발생 시 팀원들과 즉시 공유하였는가?
- [ ] 특정 팀원에게 업무가 과도하게 집중되지 않았는가?
- [ ] 작업 시작 전 Git 저장소를 최신화하였는가?
- [ ] 다른 팀원의 PR 및 병합된 변경 사항을 확인하였는가?
- [ ] 기능 테스트 및 예외 상황 검토를 충분히 진행하였는가?
- [ ] 발표 자료와 프로젝트 문서를 기한 내 완료하고 최종 검토하였는가?
